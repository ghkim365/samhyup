💡 인프라 전환 핵심 요약 (2026-11-19)

기존 Vercel의 무료 플랜(Hobby)은 월간 대역폭(100GB) 제한 및 상업용 B2B 서비스 운영에 따른 제재/과금 위험이 상존했습니다.
이에 따라 대역폭과 요청 수가 완전 무제한 무료이며, 국내 통신 3사(서울 PoP) 직결로 초고속 로딩을 제공하는 Cloudflare Pages로 인프라를 성공적으로 전환하였습니다.
또한 배포 용량 최적화를 위해 archive/ 폴더와 임시 스크립트 등을 100% 분리·제외하고, 대시보드와 카탈로그 파일명을 명시적 명명 체계(index_dashboard / index_catalog)로 전면 개편하여 혼선을 원천 차단했습니다.

3. ⚠️ Cloudflare 배포 시 절대 헤매지 않는 핵심 교훈 (Fail-Safe Guide)

🚨 [주의 1] Cloudflare 새 UI에서 "Workers"로 빠지는 함정 주의!

Cloudflare 대시보드가 최근 Workers & Pages로 메뉴를 통합하면서, Create an app에서 GitHub을 선택하면 정적 사이트(Pages)가 아닌 서버리스 코드 실행용인 'Worker' 프로젝트(npx wrangler deploy)로 생성되어 버립니다.
이 상태에서는 정적 HTML 사이트 배포 시 wrangler.toml 누락 또는 인증 토큰 오류([ERROR] Code: 10000)가 계속 발생합니다.
👉 해결책: 복잡한 Git CI 빌드 대신, Pages 프로젝트의 Direct Upload(폴더 드래그 앤 드롭) 방식을 사용하면 단 5초 만에 오류 없이 100% 배포가 완료됩니다!

💡 [주의 2] 여러 폴더의 index.html 난립에 따른 혼선 원천 차단!

루트에도 index.html, catalog에도 index.html 등 동일한 파일명이 중복되면 라우팅과 링크 관리에서 심각한 혼선이 발생합니다.
👉 해결책 (2026-11-19 확정 표준 체계):
• 루트 대문(index.html): 메인 접속 시 index_dashboard.html로 자동 이동하는 리다이렉터 전용 파일로만 사용.
• 영업 대시보드(index_dashboard.html): 관리자 전용 모니터링 화면으로 명확히 명명.
• 고객 카탈로그(catalog/index_catalog.html): 고객에게 메일/견적서 발송 시 연동되는 카탈로그 전용 파일로 명확히 명명.
• 대시보드 하단 바로가기: index_dashboard.html 하단에 카탈로그 및 브로슈어로 1클릭 이동/링크 복사 네비게이션을 상시 배치.

배포를 고쳤는데도 내 브라우저에서만 첫 페이지가 예전 화면(관리자 대시보드)으로 나오거나 디자인이 갱신되지 않을 때의 점검·정리 절차입니다.

• 증상: https://samhyup.pages.dev/ 접속 시 카탈로그가 아닌 index_dashboard가 열림 / 수정한 헤더·버튼이 반영되지 않음
• 원인: 예전에 등록된 서비스워커(sw.js)와 브라우저 캐시가 옛 화면을 서버보다 먼저 보여줌. 서버(_redirects, _headers) 설정과는 무관
• 가장 빠른 진단: 시크릿(비공개) 창에서 열어 정상이면 서버는 정상, 일반 브라우저의 캐시 문제로 확정

🛠️ 정리 방법 (기기마다 1회)

환경 정리 절차
PC Chrome / Edge
(빠른 방법)		 1. 해당 사이트에서 F12 → Application 탭 → Service Workers → Unregister
2. 같은 탭의 Storage → Clear site data
3. 새로고침(Ctrl + F5)
PC 일반 방법 Ctrl + Shift + Delete → 기간 전체 → 쿠키 및 기타 사이트 데이터, 캐시된 이미지 및 파일 체크 → 삭제
모바일 Chrome 설정 → 개인정보 보호 및 보안 → 인터넷 사용 기록 삭제 → 쿠키 및 사이트 데이터, 캐시된 이미지 및 파일 삭제
(또는 주소창 자물쇠 → 사이트 설정 → 데이터 삭제)
홈 화면에 추가한 앱(PWA) 앱 아이콘 삭제 후 브라우저에서 다시 접속하여 홈 화면에 추가
확인 정리 후 https://samhyup.pages.dev/ 접속 → 카탈로그가 첫 화면이면 정상. 관리자 화면은 /admin 또는 카탈로그 푸터의 © 탭

📌 참고

• 일반 고객은 대부분 처음 접속하거나 서비스워커가 없어 영향이 거의 없고, 예전에 대시보드로 접속했던 직원 기기에서 주로 발생
• 서버 점검: curl -I https://samhyup.pages.dev/ 결과가 302 / Location: /catalog/index_catalog.html 이면 배포는 정상
• 기기가 많아 일괄 해결이 필요하면 루트 sw.js를 캐시 삭제·자기 해제용 킬스위치로 교체해 배포
